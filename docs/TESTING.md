# PC 업무관리 검수

공개용 합성 사례로 검수합니다. 날짜와 상품명은 테스트를 위한 값이며 실제 업무 기록으로 사용하지 않습니다.

## 범위

- 개정별 독립 저장·조회 및 동명 업무의 분리
- 부분 완료와 전체 완료, 서면 협의와 부서 회신 구분
- 반복 일정 지연·복수 선행자료·회의 예정/확정
- 완료 업무의 재산출·수정 차수
- 개발·검증·부분 오픈 단계 분리
- 한 개정 안의 안건별 일정, 공유 자료의 변경 범위
- 필수조건 제외와 업무 자체 제외의 차이
- 동시 편집 충돌, HTML 보관 및 새 상품 이관
- PC 드래그·양끝 기간 조절·다중 이동·확대·키보드 실행 취소

## 방법

Chromium을 기본으로 1280/1440/1920px 창에서 확인합니다. 검수 DB·프로필·다운로드는 임시 폴더로 분리합니다. fixture는 입력 준비용이며 원문 업무 데이터를 가져오지 않습니다. 사례 명세는 `tests/fixtures/channel_scenarios.json`에 있습니다.

결과는 통과·부분 통과·실패·입력 확인·기능 공백을 구분합니다. 전용 기능이 없는 항목을 통과로 표시하지 않습니다. 실제 Ctrl+클릭 선택 과정과 지원범위 밖 마우스 드래그 등은 별도 수동 검수가 필요합니다.

검수 증거는 로컬 `docs/evidence/`에 생성됩니다. 파일이나 화면에 입력한 실제 업무 자료가 공개 커밋에 섞이지 않도록 해당 디렉터리는 기본 제외합니다.

## 주의할 현행 동작

상품위원회는 부서장협의회 일자로부터 5영업일 이후에 잡을 수 있습니다(2026-10-23 수정 요청 반영). 과거 사례와 간격이 다른 사실만으로 제품 오류로 판정하지 않으며, 새로 입력·변경하는 일정에서 규칙이 정확히 적용되는지 확인합니다. 후행 일정은 자동으로 앞당기지 않습니다.

## 일정 변경 미리보기 원복 (2026-10-23)

## 판매개시 기록 분리 (2026-10-23)

상품안 부서별 검토가 사용하던 메모 목록과 판매개시의 날짜·확정 상태·사용자 메모·시스템 메모를 별도 기록으로 분리했습니다. 판매준비 업무의 일정 변경 알림은 판매개시 상세에서만 표시합니다. 개정별 기존 저장 및 HTML 보관 형식을 유지하기 위해 해당 개정의 업무 데이터 안에 독립된 `saleDetails` 객체를 저장하며 서버 프로그램 변경은 필요하지 않습니다.

기존 데이터의 판매개시일·확정 여부와 식별 가능한 판매개시 시스템 메모를 이전합니다. 시스템 메모의 ID·등록 시각·확인 여부를 보존하며 반복해서 읽어도 메모가 중복되지 않습니다. 기존 사용자 메모와 용도를 판별할 수 없는 기록은 원래 업무에 남깁니다. 업무 날짜가 초기 템플릿과 같더라도 사용자 기록이 있으면 초기화하지 않습니다.

검수 범위: 기존 데이터 이전, 상품안과 판매개시의 메모 표시 분리, 판매개시 사용자 메모 작성 및 시스템 메모 삭제·실행 취소, 판매개시일 편집, 서버 저장·재조회, HTML 내보내기·재열기·새 개정 가져오기.

검증 결과: 브라우저 핵심 검사 34개, 서버 API 21개, 날짜 계산 18개 및 JavaScript 구문 4개 블록이 통과했습니다.

## 10월 23일 추가 요청 반영

- 상품위원회 최소 간격을 5영업일로 통일했습니다. 새 상품 기본 일정, 회의일 입력 검증 및 선행 지연 전파 계산에 같은 기준을 사용합니다. 기존 회의일을 일괄 앞당기지는 않습니다.
- 회의일 오류는 휴일 → 상품위원회 간격 → 필수 업무 종료일 순으로 하나만 표시합니다. 종료일 안내에는 가장 늦게 끝나는 필수 업무 한 개만 표시합니다. 지원 범위를 벗어난 날짜는 별도 안내합니다.
- 사용자·시스템 메모를 합쳐 최신 한 개를 표시하고, 나머지는 펼쳐 볼 수 있습니다. 차트 막대 툴팁에도 최신 메모 한 개만 표시합니다.
- 시스템 메모 삭제 버튼을 제거했습니다. 사용자 메모의 수정·삭제·실행 취소는 유지합니다.
- 선행·후행 업무는 각각 첫 항목을 표시하고 나머지는 펼쳐 봅니다. 항목이 없으면 ‘없음’을 표시합니다.
- 직접 추가한 업무는 필수 완료 대상에 자동 편입하지 않으며, 추가 자체로 회의일이나 판매개시일을 변경하지 않습니다. 표준 필수 업무의 새 차수는 계속 최신 차수로 판단합니다.

이번 검수에는 5영업일 경계값, 오류 우선순위, 단계별 추가 업무의 영향, 실제 펼치기·사용자 메모 수정/삭제, 판매개시 기록 분리와 저장·HTML 이관 회귀 검사를 포함합니다. 이전 날짜에 기록된 검수 결과는 당시 규칙을 기준으로 한 이력입니다.

검증 결과: 브라우저 핵심 검사 59개, 날짜 계산 18개 및 JavaScript 구문 4개 블록이 통과했습니다. 개정 시나리오 중 REV-09(직접 추가 업무의 차수)·REV-20(표준 필수 업무의 제외·복원)도 새 기준으로 확인했습니다.

## 차수 삭제와 차수 입력 디자인 (2026-10-23)

차수 선택·추가·삭제를 한 줄 도구 모음으로 모으고 추가 폼은 시작일·완료일 두 칸과 추가/취소 버튼으로 정리했습니다. 추가한 2차 이후의 선택 차수를 삭제할 수 있으며 1차 원본은 보호합니다. 중간 차수를 삭제해도 남은 차수 번호는 바꾸지 않습니다.

삭제되는 차수를 직접 참조하는 업무는 직전 차수로 다시 연결합니다. 중복 선행관계를 합치고 FS/FF가 겹치면 더 엄격한 FS 관계를 유지합니다. 연결 오류가 생기는 삭제는 반영하지 않습니다. 다른 업무의 일정과 완료 상태는 그대로 유지하며 삭제한 차수의 일정·메모·연결 관계는 한 번의 실행 취소로 복구할 수 있습니다. 삭제 전 확인창을 제공합니다.

PC 상세창을 열었을 때 대화 버튼이 메모 저장 버튼을 가리지 않도록 대화 버튼과 패널을 상세창 왼쪽으로 이동했습니다.

관련 브라우저 검사 16개(추가/취소·중간/마지막 삭제·선행관계 정리·1차 보호·필수 차수 복귀·실행 취소·서버 저장 재조회), 날짜 계산 18개와 JavaScript 구문 검사가 통과했습니다. PC의 추가 폼과 삭제 도구 모음도 확인했습니다.

최종 차수 도구 모음의 가로 배치도 추가 검수했습니다. 실제 2차 생성 후 차수 버튼의 높이가 같은지 확인하는 브라우저 검사 포함 5개가 통과했습니다.

## 차수 추가 버튼 표시 보완 (2026-10-23)

차수 추가 조건을 만족할 때만 버튼과 단일 차수 목록을 표시하던 조건을 제거했습니다. 업무 상세에 ‘+ 차수’를 항상 표시하고, 추가할 수 없는 경우 비활성화와 툴팁으로 이유를 안내합니다. 마지막 차수 완료 후 추가 가능, 해당없음 업무 제외, 상품안 부서별 검토의 기존 차수 추가 제한은 유지합니다. 완료 여부를 바꾸면 버튼 상태가 즉시 갱신됩니다.

관련 브라우저 검사 9개, 날짜 계산 18개 및 JavaScript 구문 검사가 통과했습니다.

## 일정 옆 차수 추가와 선택 (2026-10-23)

‘+ 차수’를 업무 상세 일정 범위 오른쪽으로 옮겼습니다. 1차만 있는 경우 차수 선택 표시는 숨기고, 추가 차수가 생기면 일정 항목 안에 1차·2차 등의 선택과 선택 차수 삭제를 표시합니다. 소요일수 아래에 별도 차수 도구 모음을 두지 않습니다.

버튼 자체를 비활성화하지 않고 클릭하면 입력 폼을 엽니다. 미완료·이전 차수·해당없음·상품안 검토의 제한은 화면에 이유를 표시하고 실제 제출 버튼을 비활성화하여 안내합니다. 마지막 차수 완료 후 추가하는 기존 업무 규칙은 유지합니다.
